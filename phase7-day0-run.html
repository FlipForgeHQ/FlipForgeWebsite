PHASE 7 · CONTROLLED PROOF STUDY

Day-0 25-card run

This is the operator guide for the prospectively frozen FF_25_CARD_PROOF_V1 study. The target identities, listing-selection rule, saved 25-of-25 selection, and final cohort membership are governed before later outcomes exist.

Frozen study: 25 exact targets · 7 MLB / 6 NFL / 6 NBA / 6 NHL. SQLite remains the proof source of truth. The accepted Day-0 selection is additionally protected by its SHA-256 fingerprint.

1 · Confirm hosted provider readiness

Run the private provider preflight in the authorized FlipForge backend runtime before making any live marketplace query.

java -cp /app/FlipForge.jar com.flipforge2.saas.SaaSProofDay0ListingSelectionOperator preflight

Continue only when the result reports ready=true. Preflight performs no marketplace search, exposes no credential value, and creates no Day-0 decision.

2 · Save the governed 25-of-25 selection as JSON

Run the live selector once and save its authoritative JSON result. Do not generate the proof CSV directly from a second marketplace search.

java -cp /app/FlipForge.jar com.flipforge2.saas.SaaSProofDay0ListingSelectionOperator select \
  --format json \
  --output /data/proof/FF_25_CARD_PROOF_V1-day0-selection-YYYYMMDD.json

The selector keeps only eligible exact fixed-price matches from the governed authorized eBay API result set. It does not claim market-wide cheapest-listing coverage, and active asks never become sold evidence.

3 · Fingerprint and lock that exact JSON

Record the SHA-256 of the accepted complete 25-of-25 JSON file. Once accepted and fingerprinted, do not rerun selection for this proof study.

sha256sum /data/proof/FF_25_CARD_PROOF_V1-day0-selection-YYYYMMDD.json
Current accepted V1 fingerprint: 0c9373ea0619a44d8168ecfc10e28d8c8bae5aeb66dc5458141d0f7b36b30c1f

4 · Export Bulk Evaluate CSV from the locked JSON

Use export-locked with the recorded fingerprint. This performs no provider search and refuses a modified or mismatched selection file.

java -cp /app/FlipForge.jar com.flipforge2.saas.SaaSProofDay0ListingSelectionOperator export-locked \
  --input /data/proof/FF_25_CARD_PROOF_V1-day0-selection-YYYYMMDD.json \
  --sha256 0c9373ea0619a44d8168ecfc10e28d8c8bae5aeb66dc5458141d0f7b36b30c1f \
  --output /data/proof/FF_25_CARD_PROOF_V1-day0-bulk-evaluate-YYYYMMDD.csv

6 · Let proof mode preflight all 25 identities

This is a separate identity preflight. Bulk Evaluate verifies all 25 card identities through server-owned Identity Intelligence before submitting any Day-0 evaluation. If one identity is ambiguous, the entire proof batch stops before Day 0 rather than partially evaluating the cohort.

7 · Export the completed Day-0 proof IDs

After all 25 authoritative evaluations complete, download the Day-0 proof-ID audit handoff. Preserve all 25 request IDs exactly as returned. The browser export remains audit-only; it cannot create or mutate the proof cohort.

8 · Freeze the cohort against the original locked selection

Use the new private locked-freeze operator. It re-verifies the original JSON SHA-256 and independently binds every completed evaluation to exactly one locked marketplace listing and its Day-0 all-in ask before creating immutable cohort membership.

java -cp /app/FlipForge.jar com.flipforge2.saas.SaaSProofDay0CohortFreezeOperator freeze25 \
  --tenant <trusted-tenant-context> \
  --database /data/flipforge2.sqlite \
  --selection-file /data/proof/FF_25_CARD_PROOF_V1-day0-selection-YYYYMMDD.json \
  --selection-sha256 0c9373ea0619a44d8168ecfc10e28d8c8bae5aeb66dc5458141d0f7b36b30c1f \
  --cohort-id FF-PROOF-25-V1 \
  --name "FlipForge 25-Card Four-Sport Proof V1" \
  --request-id <day0-request-1> \
  ... repeat --request-id exactly 25 times ...

Accept the freeze only when it reports phase7LockedSelectionVerified=true, the exact locked SHA-256, phase7VerifiedRequestCount=25, memberCount=25, and day0SnapshotCount=25.
