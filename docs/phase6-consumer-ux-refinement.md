# Phase 6 Consumer UX Refinement

This phase removes customer-facing engineering language from the current SaaS surface without changing any intelligence authority.

## Scope

- Lock the product descriptor to **Card Intelligence** in the SaaS app shell.
- Present CardSight-backed matching as FlipForge **Identity Intelligence** rather than a provider-facing diagnostic surface.
- Present Forge Heat as **Pro Card Intelligence** while retaining its saved-evaluation scope.
- Replace low-level browser/contract diagnostics with customer-safe retry copy.
- Improve empty/error state presentation and reduce the visual weight of implementation-boundary notes.

## Authority preserved

- Smart Opportunity remains the sole BUY/WATCH/VERIFY/PASS authority.
- Existing PSA intelligence remains the grading-guidance authority.
- The refinement layer performs no API calls and computes no Heat, supported value, evidence acceptance, or recommendation.
- No billing or transaction authority changes are included.

## Validation

Dedicated validation checks brand wording, mounted assets, customer-safe state copy, mobile state styling, and confirms that the refinement layer does not introduce API calls or decision calculations. Existing consumer navigation, CardSight customer identity, and customer-intelligence authority validation are retained in CI.
